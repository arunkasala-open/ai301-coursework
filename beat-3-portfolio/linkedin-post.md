# My First Open-Source Contribution to qim3d

During this fall, I got an opportunity to work on my first open-source software contribution through a project called qim3d. It was an interesting experience because I got to work with an existing software project that is used by scientists for analyzing 3D images, including images of different materials. Since this was my first contribution, I wanted to understand how an open-source project works and how even small improvements can make a difference for other developers.

While exploring the project, I noticed a few issues with how some of the test cases were organized. These tests are useful because they help developers check whether the software is still working properly after making changes. I found that one test file containing four tests was placed in a folder that was no longer relevant to the project. I also noticed that another large test file, with almost 400 lines of code, contained tests for two different features instead of keeping them separate. The project maintainer had already pointed out these issues and was looking for someone to help improve the organization.

To fix these issues, I started by splitting the large test file into two separate files, with each file focusing on a different feature. I also reorganized the four tests from the misplaced file by moving them into two new files located next to the related code they test. After moving the tests, I removed the unnecessary empty folder. My main goal was to make the project easier to understand and help other developers find the tests they need without confusion.

One important thing I learned during this work was that making changes to an existing project requires careful verification. I did not want my file organization changes to accidentally remove or affect any existing tests. So, before making the changes, I created a list of all the tests and compared it with the list after completing the work. The comparison showed that all 43 tests were still present, with exactly the same names as before. I also ran the project's test suite and confirmed that all 318 tests were passing.

At the moment, I have submitted my contribution and it is waiting for review from the project maintainers. Overall, this experience helped me understand how open-source development works in practice. I learned that contributing to a project is not always about adding new features or writing a lot of code. Sometimes, improving the organization of existing code is also valuable. Most importantly, I learned to follow the project's existing guidelines, make changes carefully, and provide evidence that my work has not affected the existing functionality.
